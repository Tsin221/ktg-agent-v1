# S3-03 状态并发与单据冻结：实施与验收记录

日期：2026-10-13。范围：物料入库单 `IR` 与生产领料单 `ISSUE` 的现有页面入口和 S3-02 统一执行服务。

## 本任务做什么、预期得到什么

| 工作 | 预期结果 |
| --- | --- |
| 给两类单据表头增加持久化 `version`，每次表头或明细修改递增 | 预览时读取的版本可与执行时版本比对；过期预览得到 `DOCUMENT_VERSION_CONFLICT`，无库存写入 |
| 让表头、明细的增改删、入库确认和执行共同锁定表头行 | 执行与编辑互斥；执行先提交时编辑返回冲突，编辑先提交时带旧版本的执行返回冲突 |
| 在执行事务中重新检查状态、编号、明细数量及物料/单位/批次/仓储关键字段 | 仅 `APPROVED` 可执行；非法状态、空行、无效行在库存变化前拒绝 |
| 完成状态与库存/流水/回执一起提交；冻结已完成单据 | 失败整体回滚；`FINISHED` 或 `CANCELED` 的来源数据不能通过普通编辑、删除或确认改变 |

## 实现

- `20261013_s3_03_inventory_document_version.sql` 给两个表头增加非空版本列，重复执行安全。`scripts/apply-db-migrations.ps1` 已登记在 S3-02 之后。
- `InventoryDocumentGuard` 以表头 `SELECT ... FOR UPDATE` 作为单据所有修改的共同锁。四个表头/明细 Service 的写方法在事务内加锁，明细更改后递增所属表头版本；批量删除先按表头 ID 排序锁定并校验，再删除，避免部分提交。行不允许改挂到其他单据。
- 表头普通更新禁止客户端把状态直接设为 `FINISHED`，并校验 `PREPARE → APPROVING → APPROVED` 的页面提交链；`PREPARE/APPROVING/APPROVED → CANCELED` 和原入库确认的 `PREPARE → CONFIRMED` 仍可用。相同状态下保存允许，但仍递增版本。`FINISHED`、`CANCELED` 冻结。
- 两个旧 `PUT /mes/wm/.../{id}` 执行路由接受可选 `X-Document-Version`。页面列表将当前版本传给执行接口；缺省调用仍靠表头行锁、状态白名单及 S3-02 单据唯一键防重复。S3-02 旧请求未带版本时的请求摘要保持原算法，保证旧回执可重放。
- 执行服务在持有表头锁后重新读取明细；明细修改入口先锁同一表头，因而执行事务内的明细快照不会被这些入口穿插改写。写入后逐行核对流水类型、方向、数量和单位，再置终态。事务失败抛异常，库存/流水/完成状态回滚；拒绝或失败回执按 S3-02 的独立事务落库。
