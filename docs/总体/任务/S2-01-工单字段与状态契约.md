完成依据：[第二阶段独立复查与修复验收报告](../../第二阶段工单草稿复查与修复验收-2026-10-11.md)。本完成标记限于独立验收环境；正式环境迁移、完整构建和操作员授权仍待执行。下方原验收清单保留立项时的勾选状态，证据范围以验收报告为准。

## 任务

核对 `ProWorkorder`、`ProWorkorderMapper.xml`、生产工单数据库表、前端 `workorder.js` 和 `index.vue`。逐项写明创建草稿、编辑草稿、查询、确认、完成、取消所需字段及当前实现。重点处理前端要求的 `workorderType`：确认实际业务是否必须保留；若保留，则补齐数据库列、实体、Mapper、查询和迁移；若业务决定不保留，则统一移除页面相关输入、筛选和条件显示。不能只在前端隐藏问题。

明确草稿状态 `PREPARE` 的创建默认值、可编辑字段、数量与日期含义、工单编号唯一性、产品关联的真实数据来源。确认、完成、取消必须定义为独立动作；本阶段只安排草稿写入，其他动作在契约中注明当前可用性，不擅自新增业务功能。

## 原验收标准（立项清单）

- [ ] 字段表覆盖页面字段、Java 实体、Mapper、数据库列和 Agent 工具输入；不一致项均有明确处理结论。
- [ ] 新建和查询草稿能一致保存/返回 `workorderType`，或页面与业务一致地不再使用它。
- [ ] `finish`、`cancel`、`listWithTaskJson` 等前端声明已逐项标出后端实际可用性和处理方式。
- [ ] 迁移可在测试库执行，并有既有数据的默认值或回填策略；未执行迁移时不能标记字段已对齐。
