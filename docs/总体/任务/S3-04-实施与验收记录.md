# S3-04 库存余额与流水原子性：实施与验收记录

日期：2026-10-13。范围：`WmTransactionServiceImpl` 的库存增减、`StorageCoreServiceImpl` 的一组业务流水，以及 S3-02/03 已建立的入库和领料执行事务。

## 做什么、预期得到什么

| 工作 | 预期结果 |
| --- | --- |
| 给库存余额定义数据库业务唯一维度 | 两笔同维度并发入库只有一条余额；跨仓库或库位仍分开 |
| 用 SQL 原子累加和带足量谓词的扣减代替 Java 读改写 | 多实例并发不丢更新；要求足量的出库不透支 |
| 校验正数、两位精度、方向、单位、来源单据行，检查写入行数 | 非法交易或流水写入失败不会留下余额变化 |
| 在仓储核心服务上建立事务边界，并沿用 S3-02/03 的执行事务 | 领料出入两腿、单据终态、流水关联和成功回执一起提交或回滚 |
| 关闭库存余额和流水的独立增改删服务入口 | 页面或其他调用不能绕过业务交易直接改账 |
| 在独立 MySQL 库验证并发、失败注入和回滚 | 留下可重复的验收用例和迁移前检查方法 |

## 业务维度和库存不足规则

唯一维度为物料 ID、仓库 ID、库区 ID、库位 ID、供应商 ID、工单 ID、单位及批次。可空 ID 按 `0` 归一；单位和批次去除首尾空格，批次的 `NULL` 与空串归一。文本大小写按字节区分。物料、仓库和单位必填，数量必须大于零且最多两位小数。物料名称、编码、工单编码、入库时间和有效期是附加信息，不参与余额唯一性。库存余额改为 `DECIMAL(18,2) NOT NULL`，避免原 `DOUBLE(12,2)` 的二进制浮点误差。

入库用业务唯一键约束下的 `INSERT ... ON DUPLICATE KEY UPDATE quantity_onhand = quantity_onhand + ...`。出库用 `UPDATE quantity_onhand = quantity_onhand - ...`；要求足量时增加 `quantity_onhand >= ...`，影响行数不为 1 即失败。生产领料明确开启足量检查。既有消耗、退料等明确关闭足量检查的动作仍可从空余额生成负库存；这是现有业务策略，其他动作不能借默认值绕开领料检查。

流水继续保留来源单据类型、ID、编号、行 ID、方向和带符号数量。当前可执行的入库、领料动作由 S3-02 的 `wm_inventory_operation_transaction` 关联到操作回执；回执、关联、单据终态和余额在同一执行事务中提交。失败时已预留回执按 S3-02 规则单独记为失败，不伪称成功。其他尚未接入统一执行服务的库存动作要在后续动作任务中接入回执契约后才能开放给 Agent。

## 迁移前检查和部署

在**每个目标库**先运行只读的 [`s3-04-stock-preflight.sql`](../../../scripts/tests/s3-04-stock-preflight.sql)，保存空数量、无效维度及重复维度查询结果。若有重复余额，先结合流水和业务审计核实，不能静默合并或删除。`20261013_s3_04_stock_atomicity.sql` 建唯一键时会因重复维度失败，需人工决定修复方式。代码切换前必须先应用迁移；迁移在 `scripts/apply-db-migrations.ps1` 中登记于 S3-02/03 后。

本次对本机 MySQL 默认库只读预检：空数量 `0`、无效维度 `0`，重复维度查询无行。本次没有在该库应用 S3-04 迁移，也没有执行库存写入。

原 `/mes/wm/wmstock` 的新增、编辑、删除请求现在由服务层拒绝；如需人工盘点调整，后续必须建立有来源单据行、操作回执和流水的专用调整动作，不能恢复直接改余额。直接改写流水的服务方法同样被拒绝。

## 验证

独立库 `ktg_s304_atomicity_test` 从现有库存和流水表结构复制两张空表；应用 S3-04 迁移、S3-02 回执迁移及 [`s3-04-mysql-fixture.sql`](../../../scripts/tests/s3-04-mysql-fixture.sql)。S3-04 迁移重复执行成功。加载仓库根目录的 `use-java8.ps1`、`use-local-secrets.ps1`，设置 `KTG_S304_MYSQL_DB=ktg_s304_atomicity_test` 后运行 `WmTransactionAtomicityTest`。测试只清理并写入该专用库。

真实 MySQL 服务层测试 **10 项通过、0 失败**：两个不同 Spring 服务实例和不同数据库连接同维度并发入库；并发足量出库只有一笔成功；空批次归一和跨仓库分离；数量精度/方向拒绝；明确允许的负库存；领料第二腿故障回滚；真实入库的余额、流水、单据终态、成功回执一起提交；真实领料双腿一起提交；目标入库故障时来源扣减、流水和单据终态回滚，失败回执保留；独立余额/流水写服务拒绝改账。测试中的单据明细由测试桩提供，库存服务、MyBatis SQL、执行服务和 MySQL 事务使用真实实现。

另外用 [`s3-04-process-inbound-a.sql`](../../../scripts/tests/s3-04-process-inbound-a.sql) 和 [`s3-04-process-inbound-b.sql`](../../../scripts/tests/s3-04-process-inbound-b.sql) 在同一专用库启动两个独立 MySQL 客户端进程：A 插入 `2.00` 后持有未提交事务 15 秒，B 在一秒后插入同维度 `3.00`。两进程结束后只读回查为 **1 条余额、`5.00` 数量**。这验证了数据库唯一键和原子累加在跨进程连接下工作。

S3-02/03 的 `InventoryOperationServiceTest` 在 H2 运行 6 项，5 项通过、1 项专用 MySQL 用例按条件跳过。Java 模块编译成功。
