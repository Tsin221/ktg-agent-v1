# S3-01 库存动作清单与执行契约

状态：S3-01 契约、独立库样本核验及普通用户接口授权测试完成（2026-10-13）；页面审批流与实际执行结果属于后续联调验收。

本文是 S3-02 至 S3-08 的实施契约，**不是已上线接口**。2026-10-13 已在独立库直接写入基线库存和测试单据，但没有调用库存执行入口或生成流水。下文“目标规则”与“现状”分开表述；现有页面限制不能充当后端安全校验。

## 首批动作与源码事实

| 动作 | 现有入口 / 权限 | 页面可执行状态 | 后端现状 | 目标允许状态 / 拒绝状态 |
| --- | --- | --- | --- | --- |
| `ITEM_RECEIPT_EXECUTE` 物料入库 | `PUT /mes/wm/itemrecpt/{recptId}`；`mes:wm:itemrecpt:edit` | 列表仅 `APPROVED` 出现执行按钮；`PREPARE → APPROVING → APPROVED` 是页面经普通 `PUT /mes/wm/itemrecpt` 更新的流程 | `execute` 不校验状态，取 `getTxBeans` 后记账并置 `FINISHED`；独立的 `PUT /mes/wm/itemrecpt/confirm` 检查有行并置 `CONFIRMED`，**不是执行入口** | 仅 `APPROVED`；拒绝 `PREPARE`、`APPROVING`、`CONFIRMED`、`FINISHED`、`CANCELED`、空值和未知值。`CONFIRMED` 与页面流程并存，不能推断为可执行 |
| `PRODUCTION_ISSUE_EXECUTE` 生产领料 | `PUT /mes/wm/issueheader/{issueId}`；`mes:wm:issueheader:edit` | 列表仅 `APPROVED` 出现“执行领出”；页面先从 `PREPARE` 提交到 `APPROVING`，再提交到 `APPROVED` | `execute` 只校验有领料行，不校验状态；没有对应 `/confirm`；记账后置 `FINISHED` | 仅 `APPROVED`；拒绝 `PREPARE`、`APPROVING`、`FINISHED`、`CANCELED`、`CONFIRMED`、空值和未知值。页面的 `checkQuantity` 不是执行事务内的校验 |

上表目标允许状态来自当前页面行为，用于 S3-03 的服务端白名单；独立测试库若显示其他合法流程，应先修订契约和测试，再开放执行。两动作都须要求单据存在、编号存在、至少一条有效明细、数量大于零、物料及单位和库存维度完整；锁定单据/明细后重新校验，并在同一数据库事务里写流水、余额、完成状态和操作回执。仅靠 `@Transactional` 无法防重复或并发竞争。

### 物料入库：字段与流水

| 项目 | 字段 / 方向 | 来源与检查 |
| --- | --- | --- |
| 单据 | `wm_item_recpt.recpt_id`, `recpt_code`, `status`, `recpt_date`, `vendor_id` | `recptId` 为单据主键；业务去重键为 `(ITEM_RECEIPT_EXECUTE, IR, recptId)`，编号用于展示和核对 |
| 明细 | `wm_item_recpt_line.line_id`, `item_id`, `item_code`, `unit_of_measure`, `batch_code`, `quantity_recived`, `warehouse_id`, `location_id`, `area_id`, `expire_date` | 注意数据库/Java 拼写为 `quantity_recived` / `quantityRecived`；仓库、库区、库位取**行**，供应商及入库日期取头；必须核验行维度和主数据一致 |
| 流水 | `wm_transaction`: `transaction_type=ITEM_RECPT`, `transaction_flag=1`, `transaction_quantity=+quantityRecived` | `source_doc_type=IR`, `source_doc_id=recptId`, `source_doc_code=recptCode`, `source_doc_line_id=lineId`；每有效行一条入库流水，回执列出实际 `transaction_id` |

`WmItemRecptMapper.getTxBeans` 使用头与行的 `LEFT JOIN`。当前 `StorageCoreServiceImpl.processItemRecpt` 只拒绝空列表，不验证每行字段；无行时连接也可能返回一条行字段为空的 Bean。目标执行必须单独验证有效行，并拒绝空 ID、数量、单位、仓储维度或来源行 ID。

### 生产领料：字段与出入两腿

| 项目 | 字段 / 方向 | 来源与检查 |
| --- | --- | --- |
| 单据 | `wm_issue_header.issue_id`, `issue_code`, `status`, `workorder_id`, `workorder_code` | 业务去重键 `(PRODUCTION_ISSUE_EXECUTE, ISSUE, issueId)`；工单号进入流水 |
| 明细 | `wm_issue_line.line_id`, `material_stock_id`, `item_id`, `item_code`, `unit_of_measure`, `batch_code`, `quantity_issued`, `warehouse_id`, `location_id`, `area_id` | 原库存 ID 和仓储维度来自行；必须验证库存记录与行中物料、批次、单位及位置匹配，且领用量大于零 |
| 出库腿 | `ITEM_ISSUE_OUT`, `transaction_flag=-1`, `transaction_quantity=-quantityIssued` | `source_doc_type=ISSUE`，`source_doc_id=issueId`，`source_doc_code=issueCode`，`source_doc_line_id=lineId`；减少行指定的原库存 |
| 入库腿 | `ITEM_ISSUE_IN`, `transaction_flag=1`, `transaction_quantity=+quantityIssued` | 目标固定为线边库：仓库 `XBK_VIRTUAL`、库区 `XBKKQ_VIRTUAL`、库位 `XBKKW_VIRTUAL` 对应的实际 ID；`material_stock_id` 重新寻址；`related_transaction_id` 指向同一行出库腿流水 ID |

两腿均须出现在同一事务和回执中，不能只报净变化为零。`WmTransactionServiceImpl.processTransaction` 会将传入数量乘以 `transactionFlag` 后存入流水，所以回执应返回**带符号的实际流水数量**。目前 `storageCheckFlag` 是 Java `boolean`，默认 `false`；`processIssue` 没有设为 `true`。现有库存不足判断因此不会生效，缺失库存时甚至会插入负数量记录。S3-04/S3-06 必须对出库腿强制原子扣减和非负余额，不能把现状写成已有保护。库存匹配还按物料、单位、批次、仓库、库区、库位、供应商、工单等维度查询，数据库唯一性须核验。

## 统一命令和操作回执（拟新增）

建议新入口 `POST /mes/wm/inventory-operations`；`GET /mes/wm/inventory-operations/{operationId}` 返回持久化结果。新入口与两个旧 `PUT` 入口最终调用同一 Java 安全执行服务。命令 JSON：

```json
{
  "actionType": "ITEM_RECEIPT_EXECUTE",
  "documentId": 101,
  "operationId": "5b58d9e6-5e2e-4f5c-94d3-8df40cb0a70f",
  "expectedStatus": "APPROVED",
  "expectedVersion": null
}
```

`actionType` 只允许已开放动作；`documentId` 是 `recptId` 或 `issueId`。单据类型由服务端从动作推导为 `IR` 或 `ISSUE`，不接受客户端任意指定。`operationId` 由调用端为一次用户确认生成并稳定保存，超时重放沿用原值；同一 ID 配不同动作、单据或预期条件返回 `OPERATION_ID_CONFLICT`。不同 ID 对同一 `(actionType, documentType, documentId)` 不得再次记账，返回 `DOCUMENT_ALREADY_EXECUTED` 并附既有操作 ID/结果。身份从当前登录会话取得，包括用户 ID、用户名与权限；不接受客户端自报执行人。`expectedStatus` 可选，但服务端白名单总是必检；`expectedVersion` 仅在 S3-03 增加持久化版本列后启用，未实现前不得伪称已校验。明细、仓库、批次和数量不从命令传入，执行时读取并冻结单据快照。

领料请求样例：`{"actionType":"PRODUCTION_ISSUE_EXECUTE","documentId":202,"operationId":"8f4f0c9a-d756-482f-a9d4-5506421c7f8e","expectedStatus":"APPROVED"}`。两个请求的 `documentId` 均是示意值，不对应真实测试库单据。

成功回执示例（示意 ID 与数量，字段名与 KTG 实体对应）：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "operationId": "8f4f0c9a-d756-482f-a9d4-5506421c7f8e",
    "operationStatus": "succeeded",
    "actionType": "PRODUCTION_ISSUE_EXECUTE",
    "documentId": 202,
    "documentCode": "ISSUE-2026-001",
    "documentStatus": "FINISHED",
    "executedBy": {"userId": 7, "userName": "operator"},
    "completedAt": "2026-10-12T10:30:00+08:00",
    "transactions": [
      {"sourceDocType": "ISSUE", "sourceDocId": 202, "sourceDocLineId": 301, "transactionId": 901, "transactionType": "ITEM_ISSUE_OUT", "transactionFlag": -1, "transactionQuantity": -2.00, "unitOfMeasure": "PCS", "relatedTransactionId": null},
      {"sourceDocType": "ISSUE", "sourceDocId": 202, "sourceDocLineId": 301, "transactionId": 902, "transactionType": "ITEM_ISSUE_IN", "transactionFlag": 1, "transactionQuantity": 2.00, "unitOfMeasure": "PCS", "relatedTransactionId": 901}
    ]
  }
}
```

入库成功的 `transactions` 为每行一条 `ITEM_RECPT`、正数量、`sourceDocType=IR`；必须返回实际持久化的流水 ID 与数量，不以预览数量代替。`executedBy`、`completedAt` 属拟新增持久化操作记录，当前 `wm_transaction`/单据没有可信的执行人、完成时间字段，不能用 `createBy`/`createTime` 充当。`GET` 查询回执应返回相同 `data` 与流水列表，另含 `queriedAt`；只有读到持久化 `succeeded` 且单据 `FINISHED`、流水集合一致，前端才展示成功。操作状态统一使用小写（与 S3-07 一致），KTG 单据状态仍使用原有大写值。

入库成功样例：`{"code":200,"data":{"operationId":"5b58d9e6-5e2e-4f5c-94d3-8df40cb0a70f","operationStatus":"succeeded","actionType":"ITEM_RECEIPT_EXECUTE","documentId":101,"documentCode":"IR-2026-001","documentStatus":"FINISHED","executedBy":{"userId":7,"userName":"operator"},"completedAt":"2026-10-12T10:30:00+08:00","transactions":[{"sourceDocType":"IR","sourceDocId":101,"sourceDocLineId":201,"transactionId":801,"transactionType":"ITEM_RECPT","transactionFlag":1,"transactionQuantity":5.00,"unitOfMeasure":"PCS","relatedTransactionId":null}]}}`。

| 情况 | 操作状态 / 错误码 | 返回语义与调用端行为 |
| --- | --- | --- |
| 同 `operationId` 同请求重放 | 原 `succeeded` / `failed` / `executing`，`replayed=true` | 原样返回已落库结果；处理中返回 `executing`，前端查询，不新增流水 |
| 同 `operationId` 不同请求 | `rejected` / `OPERATION_ID_CONFLICT` | 冲突，不能按新请求执行 |
| 不同 ID 重复执行同一单据 | `rejected` / `DOCUMENT_ALREADY_EXECUTED` | 附权威 `existingOperationId`，引导查询原结果 |
| 状态或版本冲突 | `rejected` / `DOCUMENT_STATE_CONFLICT` 或 `DOCUMENT_VERSION_CONFLICT` | 带当前状态/版本，需回读预览；无副作用 |
| 无权限 | `rejected` / `FORBIDDEN` | 403；不能透露超出权限的单据明细 |
| 库存不足 | `failed` / `INSUFFICIENT_STOCK` | 事务整体回滚，无成功流水/完成状态；可附物料、位置、可用量 |
| 明细缺失/无效 | `rejected` / `INVALID_DOCUMENT_LINES` | 不执行；返回可定位的行 ID 和原因 |
| 响应中断、提交结果无法判定 | `unknown` / `RESULT_UNKNOWN` | 不宣称失败或成功，不自动换新 ID 重试；按原 ID 查询直到权威结果确定 |

HTTP 2xx 只代表请求得到响应，**业务成功仅以 `data.operationStatus=succeeded`、持久化单据/流水一致为准**。兼容 KTG `AjaxResult.code`：业务拒绝时 `code` 不得为 200；条件冲突宜 HTTP 409、权限 403、校验 422、处理中 202，具体状态码由 S3-07 接口测试固化。查询回执示例：

```json
{"code":200,"data":{"operationId":"8f4f0c9a-d756-482f-a9d4-5506421c7f8e","operationStatus":"succeeded","actionType":"PRODUCTION_ISSUE_EXECUTE","documentId":202,"documentCode":"ISSUE-2026-001","documentStatus":"FINISHED","executedBy":{"userId":7,"userName":"operator"},"completedAt":"2026-10-12T10:30:00+08:00","transactions":[{"transactionId":901,"sourceDocLineId":301,"transactionType":"ITEM_ISSUE_OUT","transactionQuantity":-2.00},{"transactionId":902,"sourceDocLineId":301,"transactionType":"ITEM_ISSUE_IN","transactionQuantity":2.00,"relatedTransactionId":901}],"queriedAt":"2026-10-12T10:31:00+08:00"}}
```

冲突样例：`HTTP 409`，`{"code":409,"errorCode":"DOCUMENT_STATE_CONFLICT","data":{"operationId":"5b58d9e6-5e2e-4f5c-94d3-8df40cb0a70f","operationStatus":"rejected","documentId":101,"expectedStatus":"APPROVED","currentStatus":"PREPARE"}}`。未知样例：`{"code":202,"errorCode":"RESULT_UNKNOWN","data":{"operationId":"5b58d9e6-5e2e-4f5c-94d3-8df40cb0a70f","operationStatus":"unknown","documentId":101,"resultQueryPath":"/mes/wm/inventory-operations/5b58d9e6-5e2e-4f5c-94d3-8df40cb0a70f"}}`。传输完全断开时客户端本身没有响应，应展示“结果待核实”，使用原 ID 查询；不把该样例误认为当前后端已有实现。

## 现有执行入口及迁移决定

| 当前入口（均为 `PUT`） | 库存核心方法 | 决定 |
| --- | --- | --- |
| `/mes/wm/itemrecpt/{recptId}` | `processItemRecpt` | 首批：改为统一服务适配入口，沿用原页面 URL 和权限；旧请求没有操作 ID 时由服务端生成并落库，但仍用单据业务键防重复；新页面可传稳定 ID |
| `/mes/wm/issueheader/{issueId}` | `processIssue` | 同上，须同时保存两腿流水 ID |
| `/mes/wm/productrecpt/{recptId}` | `processProductRecpt` | 未开放；从线边库出、成品仓入，当前出库腿明确允许临时负库存，需单独定规则 |
| `/mes/wm/rtissue/{rtId}` | `processRtIssue` | 未开放；从线边库出、原仓入，两腿需单独核验 |
| `/mes/wm/productsalse/{salseId}` | `processProductSalse` | 未开放；单腿销售出库 |
| `/mes/wm/transfer/{transferId}` | `processTransfer` | 未开放；来源与目标仓储维度各一腿 |
| `/mes/wm/rtvendor/{rtId}` | `processRtVendor` | 未开放；供应商退货单腿出库，源码有自己的状态判断 |
| `/mes/wm/rtsalse/{rtId}` | `processRtSalse` | 未开放；销售退货单腿入库 |

前六个后续动作仍保留现有页面能力，但不得开放 Agent 工具。逐项迁移时对应旧路由必须转入同一个安全服务，不能只保护新 Agent 路由。两个首批动作迁移完成前，Agent 库存写入开关维持关闭；若旧路由仍直接调用 `StorageCoreServiceImpl`，首批动作不能标为安全可用。`/confirm`、普通编辑 `PUT /mes/wm/itemrecpt`、普通编辑 `PUT /mes/wm/issueheader`、领料拣货及明细增删改属于状态/内容变更入口，S3-03 必须在执行期间冻结，防止绕过执行快照。
