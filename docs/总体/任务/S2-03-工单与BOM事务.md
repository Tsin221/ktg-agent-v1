## 任务

把当前 Controller 的“新增工单 → 生成 BOM”和“更新工单 → 删除旧 BOM → 重建 BOM”搬入同一个 Java Service 事务。Service 接受规范化请求并控制写入顺序，Controller 只负责权限注解、参数绑定和结果返回。业务异常须触发回滚，不能在已写入后仅返回错误 JSON。

重建 BOM 前先读取旧工单，比较有效产品和数量。数量或产品未变时不重建 BOM；变化时一次事务内更新工单和 BOM。每条 BOM 行使用独立对象或明确重置对象字段，避免行间字段残留。工单编号并发重复创建由数据库唯一约束或经验证的原子策略兜底，不能只依赖先查再写。

## 原验收标准（立项清单）

- [ ] 创建过程中模拟第二条 BOM 写入失败，工单和 BOM 都不留半成品。

- [ ] 仅修改不影响 BOM 的字段，不删除或重建 BOM。
