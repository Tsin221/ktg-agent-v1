# 第二阶段任务索引：创建和编辑工单草稿

日期：2026-10-09
状态：已完成（独立环境验收，2026-10-12；正式部署待执行）

完成依据：[第二阶段独立复查与修复验收报告](../../第二阶段工单草稿复查与修复验收-2026-10-11.md)。本完成标记限于独立验收环境；正式环境迁移、完整构建和操作员授权仍待执行。各工单保留立项时的验收清单，证据范围以验收报告为准。
范围：修复工单事务、参数和状态校验，对齐前后端字段，使网页 Agent 能创建和编辑生产工单草稿。

第一阶段已由项目方确认为完成。本阶段完成的含义是：用户在悬浮窗中说出产品、数量和需求日期；Agent 查找并核实产品，展示将写入的草稿内容；操作完成后返回工单 ID、编号和 BOM 核验结果；用户还能明确指定草稿，修改其允许编辑的字段。网页原有工单表单也必须与同一套后端契约一致。

## 阶段边界

- 本阶段只开放**工单草稿**的创建和编辑。确认、完成、取消、报工和库存变动属于其他业务动作，不能由普通编辑接口顺带执行。
- Java 后端是字段、权限、状态和事务的最终校验方；Python Agent 负责理解、消歧、预览、调用与结果核验。
- 现有前端的 `finish`、`cancel` 和 `listWithTaskJson` 声明不能当作已实现后端接口；在 S2-01 判定保留或收敛其页面呈现。
- 未知写入结果不能直接重试。现有 KTG 接口缺少可靠幂等键时，应先按唯一工单编号及实际单据回读核验；无法判断时展示“结果待核实”。
- 以实际运行和测试结果判定完成。仅有 Agent 文本回复“创建成功”不算完成。
