# S2-07：Agent 工单草稿工具

状态：已完成（独立环境验收，2026-10-12；正式部署待执行）。依赖：S2-01 至 S2-04；需要第一阶段已有可用的 Agent 与 KTG 查询能力。交付：用户可在悬浮窗创建或编辑工单草稿，并看到可信业务结果。

完成依据：[第二阶段独立复查与修复验收报告](../../第二阶段工单草稿复查与修复验收-2026-10-11.md)。本完成标记限于独立验收环境；正式环境迁移、完整构建和操作员授权仍待执行。下方原验收清单保留立项时的勾选状态，证据范围以验收报告为准。

## 任务

在 Python 工具注册表中加入工单草稿预览、创建和编辑工具。模型只负责提取意图和候选字段；工具代码从 KTG 回读产品和目标工单，消除同名产品歧义，验证数量、日期、状态和版本，再调用固定的后端业务接口。工具使用当前用户身份，不接受模型传入身份或任意 URL。

写入前展示结构化预览：产品、数量、单位、需求日期、工单编号及将改变的字段。实施时依据第一阶段现有授权机制，让用户明确发出的创建/编辑意图与预览参数绑定；如第一阶段尚无这项机制，先补齐再开放写工具。写入成功后按工单 ID 回读，核对状态与关键字段；创建还核对 BOM。超时或断线时先按稳定工单编号/操作记录查询结果，不能自动再次提交。无法判定时显示“待核实”。

## 原验收标准（立项清单）

- [ ] “为产品 A 建 100 件、指定日期的工单草稿”经过产品消歧、预览、写入和回读，返回真实工单 ID/编号。
- [ ] “将工单 X 的草稿数量改为 120”只修改允许字段；非草稿或过期版本不写入。
- [ ] 模型幻觉字段、恶意单据备注、无权限身份、请求超时均不能导致未核实的成功或盲目重试。
- [ ] 写后结果卡片包含可用的工单查看入口和状态；页面列表按需刷新。
