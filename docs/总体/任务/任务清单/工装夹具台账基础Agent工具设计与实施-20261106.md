## 四、字段与业务边界

1. 编码1至64字符、名称1至100字符、品牌/型号最多100字符、备注最多250字符；拒绝未知字段和空白必填文本。字段使用snake_case入参映射后端camelCase。
2. 新增必须明确编码，不调用消耗流水的自动编号接口。工具只接受类型ID并从真实接口读取类型，codeFlag、类型编码/名称由可信类型决定，不能由模型伪造。
3. codeFlag=Y时新增数量和可用数量均为1；用户传不一致数量应拒绝而非悄悄覆盖。codeFlag=N时新增数量为0至99999999整数，拒绝布尔、小数、负数和溢出，初始可用数量等于数量。状态固定使用实际字典中的在库值（当前页面为STORE），不得把状态变更伪装为基础资料编辑。
4. 本批修改只开放名称、品牌、型号、维护方式、下一保养日期/周期、备注；编码、类型、数量、可用数量、状态不可改。这样避免用基础工具绕过领用、归还和库存流程。UI中现有编辑能力不因此移除。
5. 维护类型以真实字典为准，当前REGULAR/USAGE。REGULAR使用合法yyyy-MM-dd日期，USAGE使用正整数周期（遵守Long字段且限定业务有效范围，建议1至2147483647，单位次）。可选维护字段未给保持原值；新增未给允许为空，与现有页面一致。切换维护方式清空不适用的字段，不能意外保留旧周期/日期。历史异常记录可读，但写预览需指出无法合法合并的问题，不能自动修复未指定字段。
6. 明确清空语义：可选文本可用空字符串清空；维护日期/周期可用null清空，未提供不清空。后端mapper对文本null表示不更新，对日期/周期null会清空；必须测试正确合并，不能把用户未提供字段误清。
7. 编辑保留可信原记录中的未修改业务值；不接受模型传主键覆盖、审计字段、预留字段或任意额外属性。后端会读取类型并覆盖类型名称/codeFlag，确认前复核关联类型变化，不猜测处理。
8. 删除仅支持在库且数量等于可用数量、状态与数据格式可信的记录。预览和确认都复查。检查实际后端是否存在以toolId引用的关联，若有真实可查依赖按现有安全模式阻止关联删除；不能把按类型关联的工位资源误当作某个台账ID引用，也不能宣称预读是事务锁。无法安全判断时给清晰受限错误。
9. 不包含导入导出、自动编码、批量写、领用归还、状态切换、保养执行、历史统计和后端业务框架重构。

## 五、确认与持久化

- 复用T10确认方案：预览绑定用户、动作、规范化内容、摘要、TTL、目标/类型快照并持久化。确认时重新验证身份、对应权限、原记录及类型快照；过期、篡改、跨用户、并发变化均拒绝。
- 预览没有MES写副作用，模型不能直接调用执行定义。工具目录、动态搜索/加载和ToolRunner都要维持执行隐藏边界。
- 重复确认复用已有回执；非幂等写禁止自动重试；发送后超时或回读不能判断结果时标UNKNOWN，不自动重放，不显示成功。
- 新增回读通过精确编码定位且唯一；修改比对预期业务值；删除回读确认不存在。回读不匹配不能伪报成功。
- 独立SQLite预览库，不与会话库、类型预览或其他模块共用；新增专用配置与.env.example说明，默认写关闭，模块开关/配置跟随现有方案。
