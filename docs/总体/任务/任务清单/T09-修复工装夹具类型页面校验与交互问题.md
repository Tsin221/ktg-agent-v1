## 业务规则

1. 维持当前“是否编码管理”语义。启用编码管理（`codeFlag=Y`）时，保养维护类型必须为现有合法选项 `REGULAR` 或 `USAGE`，保养周期必须为1至2147483647的整数，不接受空值、空白、0、负数、小数、非数字和超出存储范围的数值。数据库DDL字段为有符号 `int(11)`，不能仅以Java Long上限作为验证边界。
2. 定期维护按天，按使用次数维护按次。前端和后端必须执行一致校验；直接请求接口也不能绕过。特别验证JSON数字 `1.5` 不会被自动截断成1，字符串 `"1.5"` 也不能保存。错误反馈使用清晰中文，不向用户显示Java解析堆栈。
3. 未启用编码管理（`codeFlag=N`）时，维护字段隐藏、不适用并显示“无”。写入时由后端规范化并清除不适用的维护类型、周期，避免重新打开、筛选或导出继续携带旧保养设置。
4. 编辑已存在记录时，若启用编码管理却清空周期，必须明确提示并阻止保存。不得提示成功后静默保留旧周期。切换为不编码管理则应真实清除旧维护字段。
5. 历史空值、0或其他异常周期不进行猜测性补值、批量修改或删除。列表、详情保持可打开，并合理展示缺失值；对该记录保存时要求用户按新规则补齐。用户追加明确TT061应按每使用2次保养一次，已据此定向补齐该记录，未更改其他业务字段。
