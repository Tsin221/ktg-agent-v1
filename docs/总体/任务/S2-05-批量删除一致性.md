# S2-05：批量删除一致性

状态：已完成（独立环境验收，2026-10-12；正式部署待执行）。依赖：S2-03 的事务边界、S2-04 的草稿状态规则。交付：批量删除工单与 BOM 整体成功或整体失败。

完成依据：[第二阶段独立复查与修复验收报告](../../第二阶段工单草稿复查与修复验收-2026-10-11.md)。本完成标记限于独立验收环境；正式环境迁移、完整构建和操作员授权仍待执行。下方原验收清单保留立项时的勾选状态，证据范围以验收报告为准。

## 任务

当前 Controller 在循环中检查一张工单就删除其 BOM；若后续单据不可删，之前的 BOM 已被删除。将批量删除收敛到 Service，先验证所有 ID 存在且均为可删除草稿，再在同一事务中删除关联 BOM 和工单。空 ID、重复 ID、不存在 ID、混合状态及中途数据库异常必须有明确结果。

本任务不新增 Agent 删除工具；它修复同一个工单模块的事务漏洞，避免第二阶段的草稿数据被页面其他操作破坏。

## 原验收标准（立项清单）

- [ ] A 为草稿、B 为非草稿时，批量删除失败，A/B 工单及 BOM 均未变化。
- [ ] 删除过程中制造数据库异常，全部工单及 BOM 回滚。
- [ ] 合法批量删除后没有残留 BOM；重复或不存在 ID 按契约处理。

## 验证与交接

必须查表验证删除前后数据，不只断言接口返回。与 S2-08 的工单回归一同执行。
