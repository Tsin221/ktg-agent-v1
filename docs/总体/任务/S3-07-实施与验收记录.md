# S3-07 执行结果查询与恢复：实施与验收记录

日期：2026-10-14。范围：在 S3-02/05/06 的持久化库存回执之上增加统一查询与保守恢复协议。

| 做什么 | 得到什么 |
| --- | --- |
| 按原 `operation_id` 查询持久化回执 | `GET /mes/wm/inventory-operations/{operationId}` 返回执行状态、单据状态、流水、核验时间和 `safeToRetry=false`；成功回执必须与单据终态、实际流水 ID 和关联流水 ID 集合一致 |
| 按动作及单据 ID 查询一次性执行事实 | `GET /mes/wm/inventory-operations/documents/{actionType}/{documentId}` 返回已认领操作的结果；没有认领记录时为 `unknown`，不将它解释成安全可重试 |
| 复核回执读取权限 | 查询需有对应单据的 `query` 与库存读取权限（现有菜单 `mes:wm:wmstock:list`，或已有的 `mes:wm:wmstock:query`）；回执还限制为原发起人可见。原有两个“单据 + 操作 ID”接口也施加相同权限和发起人限制 |
| 写入响应丢失后恢复 | Python 客户端一次提交后按原 ID 查询；查询也失败时返回 `unknown`，不生成新 ID 或自动再次提交；持久化 `executing` 返回 `reconciling` |
| 人工核查关联 | 查询日志包含操作 ID、单据类型/ID、流水 ID、发起人 ID、耗时及结果分类，不包含 token |

## 协议说明

`succeeded` 是经单据 `FINISHED` 与回执流水关联核验的成功；`failed`/`rejected` 来自持久化回执。`unknown` 和 `reconciling` 必须显示为“待核实”，并保留原操作 ID。当前服务端没有提供足以证明安全重试的字段，因此所有查询结果均为 `safeToRetry=false`。人工核查时用操作 ID 查回执，再用单据 ID 查一次性认领与流水，核对单据状态、余额及业务日志；不能以一次 `404` 或没有认领记录直接推断写入未发生。

权限改动意味着只持有执行编辑权限的旧页面账号还需要单据查询和库存查询权限，才能查看详细回执。不能通过放宽回执查询来绕过该要求。

## 验收结果

- Python 假 KTG 测试覆盖写响应丢失后查询成功、写入和查询双断连时不重复提交，以及 SQLite 存储重新实例化后从同一 ID 恢复成功。全套测试 113 项通过；mypy 通过。
- Java 本地 H2 服务测试覆盖残留 `executing`、他人回执不可见、无认领记录不可安全重试、成功结果回读，以及回执流水关联指向其他流水时降级为 `unknown`。服务测试 13 项中 12 项通过、1 项专用 MySQL 并发用例按环境条件跳过；构建通过。
- 在独立 MySQL 库 `ktg_s208_acceptance` 上，故障代理对入库单 930017 的写响应及首次结果查询均断连：代理记录 `WRITE_COUNT=1`、`QUERY_COUNT=1`，当时返回 `unknown`。重启 Java、重新启动 Python 查询进程后，原操作 ID `ba567d67-d524-479a-abe2-f3f9c51175c2` 返回 `succeeded`；单据为 `FINISHED`，仅有对应流水 37、38 及两条回执关联，库存余额为 2.00、1.50。没有第二次写入。
- 入库单 930015、930016 分别在写响应丢失后按原 ID 查询成功；对应操作 ID 为 `2c43cef1-cb3c-4b40-9b76-8f456be9bf22`、`97ca7c50-0ef1-4eba-a942-36f50277149b`，流水为 33/34、35/36。930015 的首次查询曾因测试时启动了旧版 Java 包得到 404，干净重建并重启后原 ID 可查；因此它仅作为重启持久性补充证据，不作为故障代理切断查询的证据。
- 领料单 930008 在写响应丢失后按原 ID `17dac8b0-b63f-4d28-9d6a-8125f1d7994a` 查询成功；单据 `FINISHED`，流水 41～44 包含来源库存出库和目标库存入库，关联关系与两条明细一致；来源余额为 1.00、1.00。
- 临时最小权限用户验证：无库存读取权限时统一操作查询返回 403；获得单据查询及库存 `list` 权限后，查询管理员操作 ID 返回 404；无认领单据返回 `unknown` 且 `safeToRetry=false`；该用户执行入库单 930018 后，只能读取自己的成功回执 `1bd7d572-2196-4b45-ba35-ec9e18cc051f`，单据 `FINISHED`、流水 39/40。临时账号和角色已软删除。
- 为隔离测试恢复展示，向 Agent 独立 SQLite 写入上述 930017 操作的同用户绑定；Agent 随后以当前登录用户身份按原 ID 查询，返回 `succeeded` 和流水 37/38。真实网页登录后刷新页面，悬浮助手显示“物料入库 · 成功”、原操作 ID 和“查看单据”。此项验证的是既有操作的页面恢复展示；未借此声称网页点击确认及真实模型预览链路已验收。

故障代理脚本为 `scripts/tests/s3-07-fault-proxy.py`；权限脚本为 `scripts/tests/s3-07-permission-smoke.ps1`。上述样本均在独立测试库，不是生产业务数据。
