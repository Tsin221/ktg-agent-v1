## 执行顺序与验收标准

1. **准备样本和前快照。** 为两个动作分别建两行已审批单据，记录单据状态和版本、每行物料/批次/仓库/数量、相关库存余额和原流水数。建立最小权限账号和受限账号。领料检查来源库存及目标线边库存。
2. **验证正常网页入口与写前拦截。** 最小权限账号通过 Agent 网页预览并确认，核对预览对象和参数、执行人、结果卡和刷新后的回执。分别验证受限账号、过期预览和预览后单据变更。拦截场景均核对无业务流水和库存变化。记录所用业务模型和入口。若仅能复跑 API 或模拟测试，标明覆盖范围，网页和真实模型用例单列。
3. **验证重复操作和故障恢复。** 两个动作分别使用新夹具覆盖重复确认、客户端断线、业务写已提交而响应丢失、服务重启后恢复查询。检查原操作 ID、写入次数、持久回执和刷新后的结果。同 ID 重试应返回原结果，换 ID 执行同一已完成单据也不得再次记账。遇到结果未知，先按原 ID 和单据核验。
4. **逐笔对账并交接。** 成功单据进入终态，回执、流水及余额一致。入库每行核对增量，领料每行核对来源扣减及线边增加。用当前版审计脚本核查重复流水、孤儿关联、负库存、非成功回执带流水及回执与流水集合不符。确认隔离实例按动作停用方式，并记录对账步骤和实际确认的负责人。回收临时账号、权限和自启的测试进程，留存操作和审计记录。
