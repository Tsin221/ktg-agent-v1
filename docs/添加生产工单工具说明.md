# 添加生产工单工具说明

工具定义参考 OpenAI 官方 [Function calling：Best practices for defining functions](https://developers.openai.com/api/docs/guides/function-calling#best-practices-for-defining-functions)：描述说明用途、适用时机、各参数语义与格式；固定值用 enum 表达；工具返回含义和执行边界明确。Agent 当前采用两阶段模式：先搜索/加载工具，加载后模型收到完整工具 schema 和参数说明；目录搜索结果中的工具简介最多展示前400字符，因此新增工具简介在开头先说明“添加生产工单”、预览用途、不会写入及网页确认边界。

## 新增预览

`ktg_preview_create_workorder_draft` 用于根据用户明确提供的信息创建工单草稿预览，不在此调用中写入；实际保存必须由用户在可信网页确认。工具内部查询产品并做完整分页与唯一性验证，名称重复时返回有限候选，不要求模型额外先查产品。模型不能编造字段或编号。

| 参数 | 中文含义、约束及新增策略 |
|---|---|
| `code_mode` | 编号模式，必填；`auto`=MES自动生成，`manual`=手工编号。 |
| `workorder_code` | 工单编号，最多64字符；手工模式必填，自动模式由MES生成。 |
| `workorder_name` | 工单名称，最多255字符，必填；须来自用户明确输入，不从产品名推造。 |
| `order_source` | 来源类型，必填；`ORDER`=客户订单，`STORE`=库存备货。 |
| `workorder_type` | 工单类型；`SELF`=自制，`OUTSOURCE`=委外，`PURCHASE`=外购。省略时采用网页默认 `SELF` 并在预览展示。 |
| `product_id` | 产品ID，只能引用可信查询结果，不得猜测。 |
| `product_code` | 产品编号/物料编码，1–64字符；可直接用用户提供的编码，由工具内部解析。 |
| `product_name` | 产品名称，1–255字符；可直接用用户提供的名称，由工具内部查找；同名时返回候选。 |
| 产品标识组合 | `product_id`、`product_code`、`product_name` 可同时提供，但必须指向同一产品。新增至少提供一种；有多个标识时用于交叉核对，不要求互斥。产品名称、规格、单位由已解析记录产生，不由模型填写。 |
| `quantity` | 生产数量，必填；0.01–99999999，最多两位有效小数，超精度拒绝、不静默舍入。 |
| `request_date` | 需求日期，必填；有效的 `yyyy-MM-dd`，只能使用用户明确给出的日期，不猜测或用示例日期。 |
| `source_code` | 来源单号，最多64字符；仅 `ORDER` 时可选，`STORE` 新增会清空。 |
| `client_id` | 客户ID，非负整数，可选；仅使用用户或可信查询确认的值，`STORE` 新增会清空。 |
| `client_code` | 客户编码，最多64字符，可选；`STORE` 新增会清空。 |
| `client_name` | 客户名称，最多255字符，可选；`STORE` 新增会清空。 |
| `batch_code` | 批次号，最多64字符，可选。 |
| `parent_id` | 父工单ID，非负整数，可选；可为0或非0，新增省略默认0。 |
| `remark` | 备注，最多500字符，可选；新增省略为空。 |

新增时必填工单名称、来源、数量、需求日期、编号模式，以及至少一种产品标识；手工编号模式另需 `workorder_code`。缺字段时一次汇总询问，不虚构默认值。`ORDER` 的来源单号和客户信息按当前网页为可选。预览返回完整业务摘要或有限产品候选，确认前不写入。

## 编辑预览与确认

`ktg_preview_edit_workorder_draft` 的 `target_workorder_code` 是必填目标编号（1–64字符）。其他字段与上表同义，但编辑时均为可选：仅修改明确提供的字段，省略表示保留原值；新增时的 `SELF` 默认和 `STORE` 清理策略不应用于编辑。

`ktg_create_workorder_draft` 与 `ktg_edit_workorder_draft` 不暴露给模型。执行参数 `preview_id` 是服务器生成、绑定当前登录用户的一次性不透明标识，只能从可信预览结果原样引用；调用仅由网页用户确认流程触发，不能由模型编造或自行调用。

## 合成调用示例

以下仅说明参数形状，日期是虚构验收值，不是默认值。

自动编号：

```json
{"code_mode":"auto","workorder_name":"验收虚构工单A","order_source":"STORE","product_code":"TEST-P01","quantity":"2.50","request_date":"2026-12-31"}
```

手工编号：

```json
{"code_mode":"manual","workorder_code":"TEST-WO-001","workorder_name":"验收虚构工单B","order_source":"ORDER","product_name":"验收虚构产品","quantity":"0.29","request_date":"2026-12-31"}
```

这些示例使用虚构数据，不会被工具自动填充或执行；网页确认仍是唯一保存入口。
