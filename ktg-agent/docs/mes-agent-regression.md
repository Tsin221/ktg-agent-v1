# MES Agent 三道固定回归题

在验收环境选定三张有明细的生产工单，将下文的 `【工单A】`、`【工单B】`、`【工单C】` 替换为实际编号。优先选产品编码不同、能查到任务和分仓库存的工单。首次登记三个编号，后续复用同一组。每次用同一账号从 MES 页面核对当时的数据，库存以本次查询时的数据为准。三道题均为只读，各自新开会话。

## 1. 跨工具查询

> 请先创建任务清单。核对生产工单【工单A】和【工单B】的状态、计划数量和产品编码，再查对应产品的分仓库存。按工单列出产品编码、状态、计划数量，以及各仓库的库存数量。查不到的字段请明确说明。

通过标准

- 两张工单的字段、产品与仓库对应关系、数量和单位均与 MES 一致。
- 清单有可见进度，答案说明未查到的字段。没有数据与数量为零能区分。
- 记录模型调用数、工具调用数，以及是否有相同参数的重复查询。

## 2. 运行中改需求

> 请先创建任务清单。按【工单A】、【工单B】、【工单C】的顺序，逐张查询工单详情、任务列表、报工记录和对应产品的分仓库存。每完成一张保存一次进度，最后按工单汇总。

等任务清单出现且运行仍在进行时，选 **调整方向**，发送：

> 改一下，只保留【工单A】。后面只需要核对这张工单的状态和任务列表，库存和报工都不用再查。

通过标准

- 新指令被消费，清单保存了反映新范围的版本，最终答复只汇报 A 的状态和任务。
- 新指令被消费后，未再启动新范围之外的查询。允许已经发出的查询随后返回。
- 如果检查事件日志，能找到原因含 `steer` 的 `task_replan_checkpoint`，以及后续成功的 `update_task`。
- 若发送新指令前运行已结束，记为未测到触发条件，在新会话重试本题。

## 3. 停止、刷新、续办

> 请先创建任务清单，为【工单A】、【工单B】、【工单C】各设一个步骤。按顺序核对每张工单的产品编码和分仓库存。每核对完一张就保存清单，最后合并三张工单的结果。

看到至少一张已完成、至少一张未完成时点 **停止后续执行**。等运行结算后刷新页面，回到原会话，选原任务并点 **继续此任务**，提交：

> 继续这个任务。沿用已经核对过的结果，只补查未完成的工单。最后给我三张工单的完整汇总。

通过标准

- 刷新后能看到同一任务和最后一次保存的清单。续办沿用原任务，生成后续清单版本。
- 已完成工单的结果进入最终汇总。工具记录能看出哪些结果被复用，哪些工单重新查了。如果确实需要重查，记录原因。
- 续办完成后汇总覆盖三张工单。若仍受额度限制，记为未通过，同时记录页面是否保留部分结果、未完成项及停止原因。
- 若停止前没有可恢复的已完成步骤，记为未测到触发条件，重新测本题。
